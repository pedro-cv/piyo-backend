# Self-hosted map

Written 2026-10-28. Goal: the app's online map must not depend on a third-party tile service or its limits. MapLibre is only the renderer (in the app and, later, in the editing tool); everything it loads comes from our own server: vector tiles, the style JSON, glyphs (fonts) and sprites. The same tile file is the app's future offline download.

## 1. What MapLibre needs and where it comes from

| MapLibre needs | File | Served by | Where it comes from |
|---|---|---|---|
| Vector tiles `z/x/y` | `deploy/data/tiles/santa-cruz.pmtiles` (10.7 MB, zoom 0–15, metro bbox) | Martin → Caddy `/tiles/santa-cruz/{z}/{x}/{y}` | `pmtiles extract` of the latest Protomaps daily planet build (OpenStreetMap data, ODbL) |
| TileJSON | generated by Martin | Caddy `/tiles/santa-cruz` | — |
| Style JSON | `deploy/data/style/style-{light,dark}.json` (71 layers each, Spanish labels) | API `/v1/map/style.json?theme=light|dark` rewrites the URLs to the current host | `@protomaps/basemaps` layer generator (`deploy/tiles/make-style.mjs`) |
| Glyphs | `deploy/data/assets/fonts/<stack>/<range>.pbf` (5 stacks) | Caddy `/assets/fonts/…` | protomaps/basemaps-assets (GitHub) |
| Sprites | `deploy/data/assets/sprites/v4/{light,dark}.{json,png}` | Caddy `/assets/sprites/…` | same repo |
| Offline map (planned, not in the app) | the same `santa-cruz.pmtiles` | Caddy `/tiles/santa-cruz.pmtiles` with range requests | — |

One command builds all of it: `bash deploy/tiles/build-tiles.sh` (verified 2026-10-28: 4,343 tiles, 63 range requests, 11 MB transferred, 16 s; fonts 5 stacks; styles 71 layers). Re-run it to refresh the basemap (a couple of times a year is enough).

## 2. Tools and why

| Tool | Role | Why this one | Licence |
|---|---|---|---|
| **Protomaps daily builds** (build.protomaps.com) | source of the planet in PMTiles, OpenStreetMap-based, v4 "basemaps" schema | Free, no key, no account; extracting a city needs only HTTP range requests (no 2 GB Java build, no Geofabrik download); refreshed daily | Data ODbL; builds free to use |
| **go-pmtiles** (`protomaps/go-pmtiles` image) | `pmtiles extract` of the bbox | Official CLI; a city extract is one command | BSD-3 |
| **PMTiles** format | one file, cloud-optimised, range-readable | No tile directory, no database; the same file is the offline download for the app (docs/03 §4 planned ~38 MB MBTiles; the real extract is 10.7 MB at z≤15) | — |
| **Martin** (`ghcr.io/maplibre/martin`) | tile server: PMTiles → z/x/y + TileJSON | Rust, single binary, ~20 MB RAM, serves PMTiles and MBTiles, maintained by the MapLibre org; can also serve PostGIS tables later (reports heat-map, line overlays) | MIT/Apache-2.0 |
| **Caddy 2** | reverse proxy, static files, automatic HTTPS | Let's Encrypt with zero config, HTTP/3, one Caddyfile for local and prod | Apache-2.0 |
| **@protomaps/basemaps** (npm) | generates the MapLibre style layers | Official style for the v4 schema, themes, `lang: "es"` labels; regenerated when the schema changes | BSD-3 |
| **protomaps/basemaps-assets** | glyphs + sprites | Pre-rendered PBF glyphs for the Noto stacks the style uses, sprites for POIs | OFL (fonts) / BSD-3 |
| **MapLibre Native Android** 11.8 | renderer in the app | Already chosen in iteration 1 | BSD-2 |

Rejected: raster tiles from `tile.openstreetmap.org` (usage policy forbids app use); OpenFreeMap (fine and free, but it is a third party and the brief asks for self-hosting; it stays as a documented fallback via `MAP_STYLE_URL`); Planetiler (works, but needs the Bolivia extract, Java and ~10 minutes per build; nothing it gives us is needed at this scale); TileServer GL (Node + MapLibre GL Native, heavier than Martin, raster rendering we do not need).

## 3. How the app uses it (`MapProvider`)

- `prod` flavor: `MapLibreMapProvider` loads `API_BASE_URL + /v1/map/style.json?theme=<light|dark>`. The API builds the style from the generated files and sets `sources.protomaps.tiles`, `glyphs` and `sprite` to absolute URLs of the deployment (from `PUBLIC_BASE_URL`, or the request's `Host`/`X-Forwarded-*` set by Caddy), so the APK contains no host-specific map configuration beyond the API base URL.
- `MAP_STYLE_URL` in `app/keys.properties` overrides the style (e.g. the OpenFreeMap "liberty" style) if the server is down or for comparison.
- `dev` flavor: the drawn `MockMapProvider`; no server at all.
- `GET /v1/map` returns the PMTiles URL and size so the "Mapa de la ciudad" card in *Datos y conexión* can show the real download size (10.2 MB now) and start the offline download (not implemented in the app yet; MapLibre Native reads a local PMTiles through its `pmtiles://` file support in newer versions or via a bundled MBTiles — next iteration).
- Text search is still Photon (OpenStreetMap, key-free, fair use). Self-hosting search would add a Java service and the OSM extract; it is the next self-hosting step if Photon's public instance becomes a limit (MAP_PROVIDERS.md §5).

## 4. Capacity and cost

Tiles are ~5–70 KB each (z13 centre tile: 67 KB). Martin serves from the page cache; a 2 vCPU VPS handles thousands of tiles/s. Egress is the only real cost (HOSTING_PRICES.md): ~24 MB per active user per month under the stated assumptions. Caddy sends `Cache-Control: public, max-age=604800` on tiles and `max-age=2592000` on assets so a CDN (Cloudflare/Bunny) in front caches almost everything if traffic grows.

## 5. Updating the basemap

```sh
cd deploy
bash tiles/build-tiles.sh          # new santa-cruz.pmtiles (atomic file replace), same assets/styles
docker compose restart martin      # reopen the file
```

Martin memory-maps the PMTiles; replacing the file while it runs is safe on Linux (old inode stays open) and the restart makes it pick the new one. The style only changes when `@protomaps/basemaps` changes major version; `npm update` in `deploy/tiles` and re-run the script.
